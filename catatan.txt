# Panduan Alur Kerja Git untuk Metode PXP (Personal Extreme Programming)
# (Catatan untuk Dokumentasi Tugas Akhir)

Metode PXP menggunakan konsep 3 Baseline (diwakili oleh 3 tingkatan branch) untuk memastikan setiap iterasi berjalan aman dan terstruktur:

1. [main]    -> Baseline Produksi: Berisi kode versi final, stabil, dan siap rilis.
2. [develop] -> Baseline Integrasi: Tempat menggabungkan fitur baru untuk diuji (System Testing).
3. [feature] -> Baseline Pengembangan: Tempat menulis kode/eksperimen fitur baru sehari-hari.

=======================================================
LANGKAH-LANGKAH SIKLUS PXP SEHARI-HARI
=======================================================

Langkah 1: Memulai Iterasi / Fitur Baru
(Tahap Design & Implementation)
Pastikan Anda selalu mulai dari branch `develop`, lalu buat branch fitur baru:
> git checkout develop
> git checkout -b feature/nama-fitur-anda

Langkah 2: Menyimpan Pekerjaan Koding
Setelah selesai menulis kode atau membuat desain, simpan perubahan Anda:
> git add .
> git commit -m "Menyelesaikan fitur ABC"

Langkah 3: Menggabungkan untuk Dites
(Tahap System Testing)
Pindah kembali ke branch `develop`, lalu gabungkan branch fitur Anda. Di tahap ini, lakukan pengujian apakah fitur baru merusak sistem atau tidak.
> git checkout develop
> git merge feature/nama-fitur-anda

Langkah 4: Merilis Versi Final
(Akhir Iterasi PXP)
Jika di branch `develop` sudah dites dan 100% aman, gabungkan ke branch `main` untuk dijadikan versi rilis yang siap didemokan ke klien/dosen.
> git checkout main
> git merge develop

=======================================================
TIPS UNTUK SIDANG/PENDADARAN TA:
=======================================================
Jika ditanya bukti penerapan iterasi PXP, tunjukkan riwayat Git (Git log) Anda. Siklus dari membuat branch fitur -> merge ke develop -> merge ke main adalah bukti nyata bahwa Anda tidak mengkoding sembarangan (waterfall), melainkan melakukan tahapan PXP (Design -> Implementation -> System Testing -> Retrospective/Rilis) di setiap fiturnya.

Bab 8 (Skema Eliminasi dan Konfigurasi Tingkat Optimisasi) memberikan kita panduan desain (Blue Print) yang absolut untuk Iterasi 3 (Modul Eliminator) yang akan kita bangun selanjutnya!
@
Berdasarkan teori Lacuna yang kamu tulis, Modul Eliminator kita nanti harus punya 4 mode (Level 0 - 3):

Level 0 (Pasif): Hanya mencetak laporan JSON/HTML (Ini yang Analyzer kita lakukan sekarang).
Level 1 (Lazy Load): Mengganti komponen dengan impor dinamis React.lazy() (bisa kita pertimbangkan).
Level 2 (Empty Body): Menghapus isi fungsi tapi membiarkan deklarasinya utuh (misal: function mati() {}).
Level 3 (Aggressive): Menghapus total node AST dari file.
